# 📖 도메인 명령 가이드 (COMMAND_GUIDE.md)

이 문서는 Compasser 프로젝트의 도메인별 개발 지침과 데이터 처리 규칙을 정의합니다. 특히 AI를 활용한 데이터 생성 및 가공 시 아래 규칙을 반드시 준수해야 합니다.

## 🏗️ 공통 원칙
- **데이터 무결성(Data Integrity)**: 사용자가 보는 텍스트 정보(Description)와 시스템이 사용하는 데이터 필드(Object/Schema)는 항상 100% 일치해야 합니다.

---

## 📅 Planner & Itinerary 도메인 (`planner/`, `itinerary/`)

### 🛠️ AI 데이터 생성을 위한 Rules
AI를 통해 추천 장소나 일정을 생성할 때 다음 사항을 프롬프트와 로직에 반영하십시오.

1. **상세 환승 경로 명시**: 대중교통 이동 정보 제공 시 단순히 출발/도착만 표기하지 않고, `[A역 탑승 -> B역 환승 -> C역 하차]`와 같은 구체적인 중간 과정을 포함해야 합니다.
2. **구체적 장소 추천**: "근처 식당에 방문하세요"와 같은 모호한 표현은 금지합니다. 해당 동선 근처의 실존하는 고평점 장소(식당/카페)를 상호명, 평점, 특징을 포함하여 최소 3~5개 선별하여 추천하십시오.
3. **비용 정보의 구체성**: `estimatedCost` 필드는 절대 빈칸이나 0원(무료 장소 제외)으로 두지 않습니다. 명확한 금액이 산출되지 않을 경우 합리적인 비용 범위(예: ₩10,000 ~ ₩20,000)를 제공하십시오.
4. **교통 요금 명칭**: 변동성이 큰 대중교통 수치(예: 1400원)를 직접 적기보다는 "대중교통 기본 요금"과 같은 일반 명칭을 사용하십시오.

### 🎨 UI 렌더링 지침
- **조건부 교통 박스**: 이동 수단이 `WALKING`이거나 이동 거리가 유의미하지 않은 경우, 시각적 노이즈를 방지하기 위해 교통 정보 섹션을 렌더링하지 않거나 숨김 처리합니다.

## 🗺️ Map 도메인 (`map/`)

### 🛰️ 경로 데이터 처리
- **현실성 검증**: AI가 생성한 경로가 물리적으로 불가능하거나(예: 마을버스로 70km 이동) 한국 지리 특성에 맞지 않는 경우, 이를 UI 레벨에서 필터링하거나 AI 모델에게 재계산을 요청하는 로직을 우선시합니다.
- **다국어 대응**: 모든 장소의 이름과 주소는 사용자의 언어 설정에 맞춰 다국어로 지오코딩 및 표시되어야 합니다.
