# 숙소 연결 후 3박 4일 재측정

기본 모델 `gemini-2.5-flash-lite`를 새 프롬프트로 두 번 호출했다. 새 입력은 밤마다
숙소를 지정한다. 비교 대상은 [이전 3박 4일 실측 표본](../2026-09-30-feasible-maps/report.md)의
같은 테마 두 건이다. 숙소 입력이 달라졌고 각 조건의 응답은 한 번뿐이므로 개선율이나
모델 성능의 일반적 추정치가 아니다.

| 항목 | 이전 두 건 | 새 두 건 |
|---|---:|---:|
| 반환한 날짜 | 8/8 | 8/8 |
| 선택 방문 | 17 | 18 |
| 밤 경계에 명시한 숙소 | 0/6 | 6/6 |
| 서로 다른 날짜에서 같은 `category+purpose`가 반복된 조합 | 2 | 1 |
| 최소 체류 위반 | 0 | 1 |
| 두 호출의 총 토큰 | 7,099 | 7,875 |
| 실제 지도 장소·인접 이동 | 이전 표본에서 측정 | 새 표본 미측정 |

새 식도락 응답은 2일차와 4일차에 `디저트 카페` 목적을 반복했다. 새 필수 일정
응답의 4일차 점심은 12:10~13:00, **50분**으로 식사 최소 60분 규칙을 어겼다.
이전 필수 일정 응답은 `공원 산책`을 3일에 걸쳐 반복했다. 목적 문구의 반복 개수만
줄었으며 실제 장소의 중복 감소는 확인되지 않았다. 새 두 입력의 날짜 간
도착지·다음 날 출발지는 모두 같은 숙소로 연결돼 입력 계약을 통과했다.

실제 Maps 수집 첫 시도는 장소 확인 미완료로 중단됐다. 사유를 안전한 코드로
확인하려는 재시도는 서울역 사전 조회부터 실패했다. 따라서 새 생성본의 장소
확인율, 같은 장소 재방문, 필수 일정 지각, 종료 시각 초과는 **미측정**이다.
실패가 섞인 지도 결과를 성공 표본으로 저장하지 않았다. 생성 원문·토큰·평가
지표는 같은 폴더의 캡처 두 개와 [report.json](report.json)에 보관했다.
