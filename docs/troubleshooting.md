# 트러블슈팅: 구버전 일정 데이터 렌더링 오류 (Silent Failure)

## 이슈 설명
`/view/:id` 경로를 통해 특정 일정을 조회할 때, 과거(3월 31일, 4월 2일 등)에 생성된 데이터가 화면에 렌더링되지 않고 빈 화면만 나타나는 현상이 발생했습니다. 콘솔에 명확한 에러 로그가 찍히지 않아 원인 파악이 어려운 Silent Failure 상태였습니다.

## 원인 분석
시스템 업그레이드 과정에서 데이터 스키마가 변경되었습니다.
- **신버전 데이터:** 모든 상세 일정이 `itineraryPlan` 객체 내부에 캡슐화되어 저장됨 (`data.itineraryPlan.days`)
- **구버전 데이터:** 상세 일정 배열이 루트 레벨에 직접 존재함 (`data.days`)

이로 인해 최신 코드에서 `itineraryPlan` 객체에 접근하려 할 때 `undefined` 에러가 발생하거나, 데이터 구조 불일치로 인해 렌더링 루프가 정상적으로 동작하지 않았습니다.

## 해결 방법
1. **강력한 데이터 정규화(Normalization):** `normalizeData` 헬퍼 함수를 도입하여, 데이터를 가져오는 즉시 최신 스키마 규격으로 변환하는 프로세스를 추가했습니다. 구버전 데이터 감지 시 자동으로 `itineraryPlan` 래퍼를 씌워 반환합니다.
2. **방어적 렌더링 로직:** 렌더링 함수(`showResults`) 내부에서 정규화된 데이터를 사용하도록 통일하고, 데이터가 파손되었거나 비어있을 경우를 위한 Fallback UI(에러 카드)를 구축했습니다.
3. **에러 추적 강화:** 라우팅 및 렌더링 전 과정에 `try-catch` 블록을 적용하고, 치명적 오류 발생 시 콘솔뿐만 아니라 사용자 화면에도 직접 에러 박스를 그려주도록 시각적 피드백을 강화했습니다.

## 결과
과거 생성된 모든 일정 데이터가 현재 UI에서 정상적으로 호환되어 출력되며, 향후 스키마 변경 시에도 유연하게 대처할 수 있는 구조를 확보했습니다.
